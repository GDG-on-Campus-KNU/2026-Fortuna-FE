# 코드 스타일 및 Git 협업 규칙 (Coding Conventions & Git Workflow)

Studycast 프로젝트의 코드 일관성과 원활한 협업을 위한 규칙 및 개발 프로세스를 정의합니다.

---

## 1. 코드 컨벤션 (Coding Conventions)

### 1) TypeScript 사용 규칙

- **Strict 모드 적용**: 코드의 타입 안전성을 최대한으로 확보하기 위해 strict 컴파일 설정을 기본으로 유지합니다.
- **`any` 사용 제한**: 임의 타입 지정을 위한 `any`는 원칙적으로 금지합니다. 불확실한 값은 `unknown`을 지정한 뒤 타입 좁히기(Type Narrowing)를 사용하거나, 구체적인 타입을 직접 정의해야 합니다.

### 2) 모듈 임포트 및 절대 경로

- **Path Alias**: 상대 경로 복잡성을 회피하기 위해 `@/*` 단축 경로를 사용합니다.
  - **권장**: `import { useContents } from '@/src/entities'`
  - **지양**: `import { useContents } from '../../../entities'`

### 3) 진입점 파일 관리 (Barrel Files)

- 개별 도메인(Entity 등) 폴더 내에 `index.ts`를 두고, 외부에서 참조할 수 있는 모듈을 명시적으로 노출시킵니다.
- 외부에서는 폴더 내부 깊숙한 개별 파일 대신, 이 `index.ts`만을 거쳐 가져오도록 제약하여 불필요한 결합도를 완화합니다.

### 4) 컴포넌트 및 파일 설계

- **함수형 컴포넌트**: 모든 컴포넌트는 React Functional Component와 React Hooks의 조합으로 작성합니다.
- **파일의 라인 수 제한**: 가독성과 단일 책임 원칙을 유지하기 위해 한 파일이 **200줄**을 초과하면 리팩토링 및 분리를 적극적으로 검토합니다.

## 2. Git 워크플로 및 브랜치 전략

우리는 효율적인 릴리즈 및 개발 통합을 위해 Git Flow와 유사한 간소화된 브랜치 모델을 사용합니다.

```
  main  (배포 버전 관리)
   ▲
   │ (정식 배포 빌드)
  release (배포 전 최종 안정화 테스트)
   ▲
   │ (개발 통합)
  dev   (기본 개발 브랜치)
   ▲
   ├── feat/1  (기능 개발)
   └── fix/2   (버그 수정)
```

### 브랜치 분류

- **`main`**: 프로덕션 배포용 최상위 브랜치.
- **`release`**: 배포 직전 테스트 및 최종 수정이 이루어지는 안정화 브랜치.
- **`dev`**: 개발 통합의 중심이 되는 기본 브랜치(Default branch).
- **작업 브랜치**: `종류/이슈번호` 형태로 분기하여 단일 작업만을 수행합니다. (예: `feat/6`, `fix/12`)

## 3. 커밋 메시지 컨벤션 (Commit Convention)

커밋 내역의 가독성 향상과 추적을 위해 아래 양식을 철저히 준수합니다.

### 커밋 메시지 포맷

```
[#이슈번호] 커밋종류: 커밋 내용 요약
```

> 예시: `[#6] feat: 데이터 모델 저장 및 불러오기`

### 커밋 종류 (Commit Type)

| 종류       | 설명                                                                 |
| :--------- | :------------------------------------------------------------------- |
| `feat`     | 새로운 기능 추가                                                     |
| `fix`      | 버그 및 에러 수정                                                    |
| `docs`     | 문서 작성 및 수정 (README, docs/\*.md 등)                            |
| `style`    | 코드 의미의 변경이 없는 포맷팅, 세미콜론 누락 수정 등 (UI 변경 아님) |
| `refactor` | 코드 구조 개선 및 리팩토링                                           |
| `test`     | 테스트 코드 추가 및 수정                                             |
| `chore`    | 빌드 업무 수정, 패키지 매니저 구성 업데이트 등                       |
